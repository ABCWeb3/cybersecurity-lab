# اختبار تحديد الموقع الجغرافي والهندسة الاجتماعية في مختبر محكوم

## الهدف والنطاق

يوضح هذا الاختبار ما قد تكشفه صفحة ويب عندما يفتحها مشارك مختبري ويمنحها إذن الموقع، ومنها:

- خطوط الطول والعرض ودقة القياس التقريبية.
- عنوان IP العام ومعلومات تقريبية مشتقة منه.
- معلومات يتيحها المتصفح عن النظام والشاشة والمتصفح، بدرجات متفاوتة.

الهدف هو تدريب المستخدم على التحقق من الرابط وفهم نافذة الإذن، وقياس أثر الموافقة داخل تجربة متفق عليها مسبقًا.

> [!CAUTION]
> نفّذ الاختبار على جهازك أو مع مشارك وافق كتابةً على النطاق والبيانات والمدة. لا ترسل الرابط إلى شخص غير مشارك، ولا تستخدم اسمًا أو صورة توهمه بأنه أمام خدمة حقيقية. الإحداثيات وملفات KML والسجلات بيانات حساسة ويجب حذفها بعد الاختبار.

## كيف يعمل الاختبار؟

1. يشغّل الفاحص صفحة Seeker على خادم محلي.
2. ينشئ ngrok عنوان HTTPS مؤقتًا يصل إلى ذلك الخادم.
3. يفتح المشارك الرابط المختبري ويقرأ طلب الإذن.
4. لا يحصل الموقع على الإحداثيات الدقيقة إلا إذا منح المشارك إذن Geolocation.
5. قد تصل معلومات أقل حساسية، مثل عنوان IP وخصائص المتصفح، حتى دون إذن الموقع بحسب المتصفح وإعداداته.

> [!IMPORTANT]
> عنوان ngrok قابل للوصول من الإنترنت أثناء تشغيل النفق؛ لذلك هذه ليست شبكة معزولة بالكامل، بل تجربة خارجية مؤقتة ومقيدة. شارك الرابط مع المشارك المحدد فقط وأوقف النفق فور انتهاء التجربة.

## بيئة الاختبار

| العنصر | القيمة المختبرة |
| --- | --- |
| نظام الفاحص | Kali Linux أو Debian حديث |
| أداة الصفحة | Seeker 1.3.1 |
| لقطة Seeker المختبرة | `7bf501a9fa2a1df918512196a2e6fc55f84ecada` |
| النفق | ngrok Agent v3 |
| المنفذ المحلي | `5050` |
| جهاز المشارك | جهاز يملكه المشارك ومخصص للتجربة |

## 1. تثبيت Seeker من المصدر الصحيح

```bash
git clone https://github.com/thewhiteh4t/seeker.git
cd seeker
git checkout 7bf501a9fa2a1df918512196a2e6fc55f84ecada
chmod +x install.sh
./install.sh
```

شرح مهم:

- `git checkout` يثبت اللقطة التي اختُبرت عليها هذه التعليمات حتى لا تتغير الواجهة دون ملاحظة.
- لا حاجة إلى تشغيل `install.sh` كاملًا بـ`sudo`؛ السكربت نفسه يطلب الصلاحية عند تثبيت الحزم اللازمة.
- اقرأ سكربتات الطرف الثالث قبل تشغيلها، حتى عندما يكون المصدر معروفًا.

تحقق من الأداة:

```bash
python3 seeker.py --version
python3 seeker.py --help
```

## 2. تثبيت ngrok

استخدم تعليمات ngrok الرسمية بدل رابط ZIP ثابت قد يتقادم. على Kali أو Debian:

```bash
curl -sSL https://ngrok-agent.s3.amazonaws.com/ngrok.asc \
  | sudo tee /etc/apt/trusted.gpg.d/ngrok.asc >/dev/null

echo "deb https://ngrok-agent.s3.amazonaws.com buster main" \
  | sudo tee /etc/apt/sources.list.d/ngrok.list

sudo apt update
sudo apt install -y ngrok
ngrok version
```

يمكن أيضًا استخدام [صفحة التنزيل الرسمية](https://download.ngrok.com/) إذا تغيرت طريقة الحزم.

## 3. ربط حساب ngrok

احصل على Authtoken من [لوحة ngrok](https://dashboard.ngrok.com/get-started/your-authtoken)، ثم نفّذ:

```bash
ngrok config add-authtoken <YOUR_AUTHTOKEN>
```

لا تضع التوكن في ملف داخل المستودع، ولا تنشر لقطة شاشة تظهره.

## 4. تشغيل Seeker

من داخل مجلد `seeker` شغّل:

```bash
python3 seeker.py -t 3 -k lab-location -p 5050
```

معنى الخيارات:

- `-t 3`: اختيار قالب WhatsApp، وهو القالب رقم 3 في اللقطة المختبرة.
- `-k lab-location`: حفظ الإحداثيات في `lab-location.kml` عند نجاح القراءة.
- `-p 5050`: تشغيل الخادم المحلي على المنفذ 5050.

استخدم بيانات مختبرية واضحة عند طلب العنوان والصورة، مثل:

```text
Group name: Authorized Location Awareness Lab
Image path: [اتركه فارغًا أو استخدم صورة مكتوبًا عليها LAB]
```

لا تستخدم اسم مجموعة حقيقية أو صورة شخص أو مؤسسة. ويمكن بدلًا من الخيار `-t 3` تشغيل الوضع التفاعلي:

```bash
python3 seeker.py -k lab-location -p 5050
```

القوالب في اللقطة المختبرة هي:

| الرقم | القالب |
| --- | --- |
| 1 | NearYou |
| 2 | Google Drive |
| 3 | WhatsApp |
| 4 | WhatsApp Redirect |
| 5 | Telegram |
| 6 | Zoom |
| 7 | Google ReCaptcha |
| 8 | Custom Link Preview |

## 5. تشغيل نفق HTTPS

اترك Seeker يعمل وافتح نافذة Terminal ثانية:

```bash
ngrok http 5050
```

ستظهر نتيجة مشابهة:

```text
Forwarding  https://example.ngrok.app -> http://localhost:5050
```

يحتاج Geolocation API في المتصفحات الحديثة إلى سياق آمن مثل HTTPS، ولذلك استخدم رابط `https://` الذي يعرضه ngrok.

إذا كانت خطة ngrok وإصداره يدعمان Basic Authentication، يمكن تقييد الوصول أكثر:

```bash
ngrok http 5050 --basic-auth='lab-user:CHANGE_THIS_PASSWORD'
```

أرسل بيانات الدخول إلى المشارك عبر قناة منفصلة، ولا تستخدم كلمة المرور النموذجية كما هي.

## 6. تنفيذ تجربة الموافقة

قبل إرسال الرابط، أخبر المشارك كتابةً بما يأتي:

- الصفحة تجربة توعوية وليست دعوة حقيقية.
- ما البيانات المتوقع ظهورها.
- أن بإمكانه اختيار `Block` أو `Allow` ومشاهدة الفرق.
- متى ستحذف البيانات.

بعد ذلك:

1. أرسل رابط ngrok إلى جهاز المشارك المحدد فقط.
2. افتح الرابط أولًا مع رفض الإذن وسجّل النتيجة العامة.
3. أعد التجربة، واسمح بالموقع إذا كان ذلك ضمن الموافقة.
4. راقب نافذة Seeker وسجّل فقط ما يلزم لإثبات النتيجة.

## 7. النتيجة المتوقعة

عند منح إذن الموقع قد تظهر نتيجة مشابهة، مع اختلاف الحقول بحسب الجهاز والمتصفح:

```text
[+] Latitude: <LAB_LATITUDE>
[+] Longitude: <LAB_LONGITUDE>
[+] Accuracy: <ACCURACY_IN_METERS>
[+] Public IP: <PUBLIC_IP>
[+] Browser: <BROWSER_FAMILY>
[+] Platform: <PLATFORM_IF_AVAILABLE>
```

ملاحظات الدقة:

- يستخدم المتصفح أفضل مصدر موقع متاح للجهاز، وقد يكون GPS أو Wi-Fi أو الشبكة أو بيانات مخزنة مؤقتًا.
- قيمة `Accuracy` تقدير لنطاق الدقة وليست ضمانًا أن النقطة مطابقة للمكان الفعلي.
- عنوان مثل `192.168.x.x` أو `10.x.x.x` عنوان خاص داخل الشبكة وليس Public IP.
- موقع IP يصف غالبًا منطقة مزود الخدمة أو نقطة الخروج، ولا يساوي الموقع الدقيق للجهاز.
- المتصفحات الحديثة تقلل تفاصيل User-Agent؛ لذلك لا تتوقع دائمًا طراز الجهاز أو إصدار النظام والمتصفح الكامل.

## 8. تحليل النتائج داخل المختبر

### ملف KML

إذا أُنشئ `lab-location.kml`، افتحه محليًا فقط بأداة خرائط مناسبة. لا ترفعه إلى خدمة خارجية إلا إذا شمل نطاق الموافقة ذلك صراحة.

### عنوان IP

استخدم `whois` فقط إذا كانت القيمة عنوانًا عامًا وكان تحليلها ضروريًا للاختبار:

```bash
whois <PUBLIC_IP>
```

لا تستخدم `whois` مع عنوان خاص مثل `192.168.1.100`، ولا تعتبر المدينة المستنتجة من IP موقعًا دقيقًا.

### معلومات المتصفح

تعامل مع User-Agent وخصائص الشاشة على أنها مؤشرات قد تكون مختصرة أو معدلة أو غير متاحة، لا تعريفًا مؤكدًا للجهاز أو صاحبه.

## 9. إيقاف التجربة وحذف البيانات

1. أوقف ngrok بالضغط على `Ctrl+C` في نافذته.
2. أوقف Seeker بالضغط على `Ctrl+C`.
3. من داخل مجلد `seeker` احذف مخرجات التجربة:

```bash
rm -f lab-location.kml
rm -f db/results.csv
rm -f logs/info.txt logs/result.txt logs/php.log
```

1. تحقق من أن رابط ngrok لم يعد يعمل.
2. أخبر المشارك بانتهاء التجربة وحذف البيانات.
3. لا تضف أيًا من الملفات السابقة إلى Git، حتى لو كانت الإحداثيات تخصك.

## استكشاف الأخطاء

| العارض | السبب المحتمل | الإجراء |
| --- | --- | --- |
| لا تظهر نافذة إذن الموقع | فتح رابط HTTP أو حظر الإذن سابقًا | استخدم رابط HTTPS وراجع أذونات الموقع في المتصفح |
| يرفض المتصفح الموقع فورًا | إذن دائم بالرفض أو سياسة جهاز | أعد تعيين إذن النطاق أو استخدم ملف متصفح تجريبيًا |
| تظهر معلومات IP فقط | لم يمنح المشارك إذن Geolocation أو تعذر تحديد الموقع | هذا سلوك متوقع؛ لا تحاول تجاوز قرار الرفض |
| رابط ngrok يعرض خطأ | Seeker متوقف أو المنفذ مختلف | تأكد من تشغيل Seeker على `5050` |
| الدقة ضعيفة | المصدر المتاح Wi-Fi أو الشبكة بدل GPS | سجّل الدقة كما هي ولا تصفها بأنها موقع مؤكد |

لا يعد التصفح الخاص مانعًا مضمونًا لتحديد الموقع؛ قد يؤثر فقط في تخزين الأذونات والبيانات بين الجلسات.

## الحماية والتوعية

- اقرأ اسم النطاق كاملًا ولا تعتمد على وجود HTTPS وحده؛ HTTPS يشفر الاتصال لكنه لا يثبت أن غرض الصفحة مشروع.
- امنح إذن الموقع فقط عندما تكون الوظيفة واضحة ومطلوبة.
- راجع أذونات المواقع دوريًا واسحب الأذونات غير اللازمة.
- قد يخفي VPN عنوان IP العام أو يغير الموقع التقريبي المستنتج منه، لكنه لا يمنع إرسال الإحداثيات إذا منح المستخدم إذن الموقع.
- درّب المستخدمين على التوقف والتحقق من المرسل عبر قناة أخرى.
- استخدم سياسات المتصفح وPermissions Policy في التطبيقات المؤسسية عند الحاجة.

## حدود الاختبار

- يعمل الوصول الدقيق إلى الموقع في سياق آمن وبموافقة المستخدم.
- تختلف الحقول والدقة حسب النظام والمتصفح والجهاز وسياسات الخصوصية.
- لا يضمن الهاتف نتيجة GPS؛ يختار النظام مصدر الموقع المناسب.
- Private Browsing وVPN ليسا بديلين عن رفض الإذن والتحقق من النطاق.
- قد تتغير واجهة Seeker أو ngrok مستقبلًا؛ لذلك ثُبتت لقطة Seeker وسُجلت الإصدارات المتوقعة.

## معايير النجاح

يعد الاختبار ناجحًا عندما:

1. يعمل رابط HTTPS على جهاز المشارك المتفق عليه.
2. يختلف السلوك بوضوح بين رفض الإذن ومنحه.
3. تظهر الإحداثيات فقط بعد الموافقة.
4. يتوقف الرابط وتُحذف ملفات KML والسجلات بعد التجربة.
