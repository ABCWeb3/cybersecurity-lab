# اختبار قابلية الشبكة المحلية لهجوم ARP Spoofing وMITM داخل مختبر معزول

## الهدف من الاختبار

يوضح هذا الاختبار كيف يمكن لجهاز موجود داخل الشبكة المحلية نفسها أن يغيّر جداول ARP مؤقتًا، بحيث تمر حركة جهاز مختبري آخر عبر جهاز الفاحص قبل وصولها إلى البوابة.

الغرض دفاعي وتعليمي: فهم الخطر، ملاحظة أثره داخل مختبر تملكه، ثم تحديد وسائل الحماية المناسبة.

> [!CAUTION]
> نفّذ الخطوات فقط داخل مختبر معزول وعلى أجهزة تملكها أو لديك تصريح مكتوب لاختبارها. لا تستخدم حسابات أو كلمات مرور حقيقية، ولا تحفظ أو تنشر حزمًا تحتوي بيانات أشخاص آخرين.

## فكرة الاختبار

تحتفظ أجهزة IPv4 داخل الشبكة المحلية بجدول يربط عنوان IP بعنوان MAC. بروتوكول ARP لا يتحقق افتراضيًا من صحة كل إعلان يستقبله، ولذلك يمكن إرسال إجابات ARP تجعل:

- جهاز الاختبار الهدف يربط عنوان البوابة بعنوان MAC الخاص بجهاز الفاحص.
- البوابة تربط عنوان جهاز الاختبار الهدف بعنوان MAC الخاص بجهاز الفاحص.

عند نجاح الخداع في الاتجاهين، يصبح المسار داخل المختبر:

```text
Test target → Security tester → Gateway
Gateway → Security tester → Test target
```

تسمى هذه الوضعية **Man-in-the-Middle (MITM)**. يحتاج جهاز الفاحص إلى إعادة توجيه الحزم حتى لا ينقطع اتصال جهاز الاختبار الهدف.

## بيئة المختبر المستخدمة

| العنصر | القيمة في المثال |
|---|---|
| واجهة جهاز الفاحص | `eth0` |
| جهاز الاختبار الهدف | `10.0.2.15` |
| البوابة | `10.0.2.1` |
| الأدوات | `arp-scan`، `arpspoof`، Wireshark |

تحقق من القيم في مختبرك ولا تنسخ العناوين كما هي إذا كانت شبكتك مختلفة.

## 1. استكشاف الشبكة وتحديد النطاق

### اكتشاف الأجهزة داخل الشبكة المحلية

```bash
sudo arp-scan --localnet
```

شرح الأمر:

- `sudo`: يمنح الأداة الصلاحية اللازمة لإرسال إطارات ARP خام.
- `arp-scan`: يرسل طلبات ARP ويعرض عناوين IP وMAC للأجهزة التي تجيب.
- `--localnet`: يستنتج نطاق الشبكة من عنوان الواجهة وقناعها، ثم يفحص ذلك النطاق المحلي.

في هذا المثال تم تحديد جهاز الاختبار الهدف:

```text
10.0.2.15
```

### معرفة البوابة الافتراضية

```bash
ip route | grep default
```

شرح الأمر:

- `ip route`: يعرض جدول التوجيه في Linux.
- `|`: يرسل نتيجة الأمر الأول إلى الأمر التالي.
- `grep default`: يعرض السطر الخاص بالمسار الافتراضي فقط.

مثال للنتيجة:

```text
default via 10.0.2.1 dev eth0
```

يعني ذلك أن البوابة هي `10.0.2.1` وأن الواجهة المستخدمة هي `eth0`.

يمكن تأكيد اسم الواجهة أيضًا باستخدام:

```bash
ip -brief address
```

## 2. حفظ الحالة الأصلية

قبل تغيير أي إعداد، تحقق من قيمة إعادة توجيه IPv4:

```bash
cat /proc/sys/net/ipv4/ip_forward
```

- القيمة `0` تعني أن إعادة التوجيه متوقفة.
- القيمة `1` تعني أنها مفعّلة مسبقًا.

سجّل القيمة الأصلية حتى تعيدها بعد الاختبار.

على جهاز الاختبار الهدف، يمكن تسجيل عنوان MAC الحالي للبوابة للمقارنة لاحقًا:

```bash
ip neigh show 10.0.2.1
```

## 3. تفعيل IP Forwarding على جهاز الفاحص

نفّذ الأمر قبل بدء ARP Spoofing حتى لا ينقطع اتصال الجهاز الهدف عند انتقال الحركة إلى جهاز الفاحص:

```bash
echo 1 | sudo tee /proc/sys/net/ipv4/ip_forward
```

شرح الأمر:

- `echo 1`: ينتج القيمة `1`.
- `|`: يمررها إلى الأمر التالي.
- `sudo tee`: يكتب القيمة بصلاحيات مرتفعة.
- `/proc/sys/net/ipv4/ip_forward`: ملف نواة Linux الذي يتحكم في إعادة توجيه حزم IPv4.

تحقق من التفعيل:

```bash
cat /proc/sys/net/ipv4/ip_forward
```

يجب أن تظهر القيمة `1`.

## 4. تنفيذ ARP Spoofing في الاتجاهين

يحتاج الاختبار إلى نافذتي Terminal منفصلتين، لأن كل أمر يستمر في إرسال إعلانات ARP حتى يتم إيقافه.

### النافذة الأولى: محاكاة البوابة أمام جهاز الاختبار الهدف

```bash
sudo arpspoof -i eth0 -t 10.0.2.15 10.0.2.1
```

معنى الخيارات:

- `-i eth0`: استخدام واجهة الشبكة `eth0`.
- `-t 10.0.2.15`: إرسال الإعلانات إلى جهاز الاختبار الهدف.
- `10.0.2.1`: الادعاء بأن عنوان البوابة مرتبط بعنوان MAC لجهاز الفاحص.

### النافذة الثانية: محاكاة جهاز الاختبار الهدف أمام البوابة

```bash
sudo arpspoof -i eth0 -t 10.0.2.1 10.0.2.15
```

معنى الخيارات:

- `-t 10.0.2.1`: إرسال الإعلانات إلى البوابة.
- `10.0.2.15`: الادعاء بأن عنوان الجهاز الهدف مرتبط بعنوان MAC لجهاز الفاحص.

> [!NOTE]
> كان أمر الاتجاه الثاني في الملخص الأصلي يحتوي خطأً كتابيًا: `10.0.2.10.0.2.15`. الصيغة الصحيحة تفصل عنوان البوابة `10.0.2.1` عن عنوان الجهاز الهدف `10.0.2.15` كما في الأمر أعلاه.

إذا كانت واجهتك `wlan0` أو اسمًا آخر، استبدل `eth0` بالاسم الذي ظهر في جدول التوجيه.

## 5. التحقق من نجاح الاختبار

على جهاز الاختبار الهدف، أعد عرض إدخال البوابة:

```bash
ip neigh show 10.0.2.1
```

إذا نجح الاختبار، قد يظهر عنوان MAC الخاص بجهاز الفاحص بدل عنوان MAC الحقيقي للبوابة. قارن النتيجة بالقيمة التي سجلتها قبل البدء.

يجب أيضًا التأكد من أن الاتصال التجريبي ما زال يعمل. انقطاعه يعني غالبًا أن IP Forwarding غير مفعّل أو أن أحد اتجاهي الخداع لا يعمل.

## 6. تحليل الحركة باستخدام Wireshark

1. افتح Wireshark على جهاز الفاحص.
2. اختر الواجهة نفسها المستخدمة في الأوامر، مثل `eth0`.
3. ابدأ الالتقاط لفترة قصيرة داخل المختبر.
4. من جهاز الاختبار الهدف، افتح خدمة HTTP مختبرية واستخدم بيانات تجريبية غير حقيقية.
5. استخدم مرشح العرض:

```text
http
```

يعرض هذا المرشح الحزم التي يتعرف عليها Wireshark كبروتوكول HTTP.

### ماذا نتوقع؟

- قد تظهر طلبات HTTP وعناوين الصفحات والرؤوس لأن HTTP غير مشفّر.
- لن يعرض المرشح محتوى HTTPS المشفّر بالطريقة نفسها.
- ظهور الحزم يثبت مرور الحركة عبر جهاز الفاحص، لكنه لا يبرر جمع بيانات حقيقية أو الاحتفاظ بها.

أوقف الالتقاط بعد الحصول على دليل مختبري كافٍ، ولا ترفع ملف `pcap` إلى مستودع عام.

## 7. إيقاف الاختبار واستعادة الحالة الطبيعية

### أوقف عمليتي ARP Spoofing أولًا

اضغط `Ctrl + C` في نافذتي `arpspoof`.

إيقاف الخداع قبل تعطيل إعادة التوجيه يقلل احتمال انقطاع الاتصال بينما لا تزال جداول ARP تحتوي القيم المؤقتة.

### أعد IP Forwarding إلى قيمته الأصلية

إذا كانت القيمة الأصلية `0`، نفّذ:

```bash
echo 0 | sudo tee /proc/sys/net/ipv4/ip_forward
```

ثم تحقق:

```bash
cat /proc/sys/net/ipv4/ip_forward
```

يجب أن تظهر القيمة `0`.

### تحقق من استعادة الشبكة

- انتظر تحديث ذاكرة ARP في الجهاز الهدف والبوابة.
- تأكد من رجوع عنوان MAC الحقيقي للبوابة باستخدام `ip neigh`.
- تحقق من الاتصال الطبيعي داخل المختبر.
- إذا بقي إدخال ARP القديم في آلة افتراضية مختبرية، افصل محولها الشبكي وأعد توصيله أو أعد تشغيل الآلة.
- احذف ملفات الالتقاط التي لا تحتاج إليها، خصوصًا إذا احتوت بيانات غير مقصودة.

## النتيجة الأمنية

يثبت الاختبار أن الأجهزة الموجودة في نطاق البث المحلي نفسه قد تكون معرضة لخداع ARP إذا لم توجد ضوابط تمنع الإعلانات المزورة. الخطر الأساسي هو تمرير حركة غير مشفرة عبر جهاز وسيط أو تعطيل الاتصال.

## وسائل الحماية

- استخدام HTTPS والتحقق من الشهادات وعدم تجاهل تحذيرات المتصفح.
- عزل أجهزة الضيوف والعملاء غير الموثوقين في VLAN منفصلة.
- تفعيل Client Isolation في شبكات Wi-Fi المناسبة.
- استخدام DHCP Snooping وDynamic ARP Inspection على المبدلات المدارة.
- مراقبة تغير عنوان MAC المرتبط بالبوابة أو ظهور إعلانات ARP غير معتادة.
- استخدام VPN موثوق عند العمل على شبكة محلية غير موثوقة.
- تجنب البروتوكولات التي ترسل بيانات حساسة من دون تشفير.

## حدود الاختبار

- يعمل ARP مع IPv4 داخل نطاق Layer 2 نفسه؛ لا يعبر الراوترات مباشرة.
- IPv6 لا يستخدم ARP، بل يعتمد على Neighbor Discovery وله اختبارات وضوابط مختلفة.
- قد تمنع إعدادات المبدل أو نقطة الوصول أو العزل بين العملاء نجاح الاختبار.
- نتيجة Wireshark تعتمد على نوع الحركة، والتشفير، وقدرة الأداة على تفسير البروتوكول.
